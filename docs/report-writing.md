# 应急要情写作辅助

页面：`/coordination/emergency-report/new`。

报告内容旁增加「AI 起草」「AI 润色」「AI 检查」，共用一个可关闭的右侧面板。原红色抬头、导航、工具栏和总结报告保留。要情名称和正文可以输入，字数按正文非空白字符计算；格式工具栏仍为外观展示。

## 使用

- 起草：写作要求选填，可补充相关事实材料；留空时生成带【待核实】占位的要情框架，也可点击「载入示例」，生成后预览。正文为空时插入，有正文时可追加或二次确认替换全文。
- 参考附件：起草面板支持点击或拖拽添加 Word（DOC/DOCX）、PDF、TXT 和 JPG/PNG/WebP 图片，最多 5 个、每个不超过 10 MB。显示文件名、大小，图片支持缩略图和展开预览，可逐项移除，校验格式、大小及重复文件。附件仅在本地暂存，尚未接入存储、内容解析或模型，不参与生成；关闭侧栏或切换功能后清空。需要参考的内容请粘贴到写作要求。
- 润色：选中正文中的文字后点击「AI 润色」可只处理选中内容；没有选区时处理全文。支持规范表述、精简内容。
- 检查：针对当前全文输出缺项和表述疑点，不自动修改正文，不代表外部事实核查。
- 采用后可撤销最近一次采用，恢复到采用前的全文。若已继续手动修改正文，则禁用该次撤销，避免丢失手动修改。生成期间或生成后正文发生变化时，禁止采用旧结果，需重新生成。
- 关闭侧栏或切换功能会取消未完成的请求；Esc 关闭侧栏并返回按钮。侧栏打开时仍可修改正文。

正文和撤销记录仅保存在当前页面内存中，刷新或离开页面会丢失。原保存、模板、上传、提交按钮仍未接业务接口。

## 演示与真实模型

未配置模型时明确显示「演示模式」，使用本地模板与关键词规则，不发送材料到外部。演示起草保留材料原文，润色仅做少量口语替换；真正的智能改写和精简由真实模型完成。不会把本地演示结果标记为 AI 生成。

开发服务器提供 `GET /api/report-writing/status` 和 `POST /api/report-writing`。真实模型需在项目根目录的 `.env.local` 配置以下服务端参数并重启 `pnpm dev`：

```dotenv
AI_API_URL=https://your-model-gateway.example/v1/chat/completions
AI_API_KEY=your-server-side-key
AI_MODEL=your-model-name
```

地址需为兼容 Chat Completions 消息格式的完整接口地址，支持 `messages`、`model` 和 `choices[0].message.content`。不要给密钥加 `VITE_` 前缀；`.env.local` 被 Git 忽略，密钥仅用于服务端请求。上游服务必须能输出指定 JSON 结构。模型错误或超时将展示错误，不自动回退或覆盖正文。单次材料上限 12000 字，请求超时为 55 秒。

服务端提示词要求保留事实、数字及不确定性，缺失信息标记【待核实】；结果仍需人工确认。

当前接口只由 Vite 开发服务器提供。`pnpm build` 产物是静态站点，不包含后端。生产接入需要部署独立后端承接相同路径、加入业务身份认证、权限和调用限额；前端接口不可用时会提示，可显式切换本地演示。

## 验证

```bash
node tests/report-writing.test.ts  # Node 22.18+，支持直接运行 TypeScript
pnpm build
pnpm lint
```

自动化检查覆盖本地演示的事实保留、缺项提示，以及服务端配置状态、输入校验、来源检查、模型响应与异常。测试中的模型请求使用模拟响应，不访问外部服务。
