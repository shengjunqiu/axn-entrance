# 移动端集成入口（/mobile）页面复刻说明

本页按参考图 `axn3.png`（1284×2778，即 **428×926 CSS 的 3 倍图**，iPhone 12/13 Pro Max 尺寸）复刻手机内的工作台页面，
外层套一个 CSS 画的 iPhone 机身。所有尺寸、色值都从原图逐像素采样/量取，不是估的。

## 与原图的差异

1. 图标字形 — 原图是定制图标，这里用 lucide 里语义最接近的替代（无对应的用文字 `AI` / `A`）
2. 云图标 — 自绘 SVG，形状与原图略有差异
3. 原图有一层平铺水印（真人姓名 + 手机号），**未复现**（不属于 UI，且含真实个人信息）
4. 手机内页面保持在 `scrollTop = 0`（原图状态），所以第三个分区「公文」只露出标题；
   该节在参考图中看不到，自行补了 3 项
5. 「常用应用」末尾的「安小能」（`#347AFB` + Bot 图标）为本次演示新增的功能入口，参考图中没有；
   追加在最后一位，不影响原有 12 个图标的行列位置。它是唯一可点的图标：点击后手机屏幕内
   切到 `https://axn-demo.pages.dev/`（`phone-browser.tsx`），返回入口是网页右上角的浮层按钮
   「‹ 返回工作台」（白底胶囊 + 阴影）。放右上角是因为页面自己的按钮都在左上角（汉堡），
   做浮层而不做导航条是为了不占网页高度。
   数据侧用 `AppItem.previewUrl` 控制，谁要加就在 `mobile-data.ts` 里补一个
6. 内嵌网页的**安全区**：iframe 里 `env(safe-area-inset-*)` 恒为 0（跨域页面也没办法自己避让），
   所以给它的是几何上的安全视口 —— 只占 `428×(926-47-31)`（47 状态栏 / 31 指示条区），
   上面画状态栏、下面画 Home 指示条，
   页面内容因此不会压在灵动岛或指示条上（与真机上没开 `viewport-fit=cover` 的网页一致）

## 怎么验证（可复用）

截图与参考图 1:1 对齐的方法（`--window-size` 给的高度不等于视口高度，实测 headless 会少 ~87px）：

```bash
chrome --headless=new --force-device-scale-factor=2 --window-size=900,1400 \
  --screenshot=/tmp/m.png --virtual-time-budget=4000 http://127.0.0.1:5199/mobile
magick /tmp/m.png -crop 856x1852+472+560 +repage -resize 1284x2778! /tmp/screen.png
```

`/tmp/screen.png` 即 1284×2778，可与 `axn3.png` 直接对比（或 `-append` 拼成上下图）。
机身/屏幕坐标也会写进 DOM，便于脚本量取：屏幕节点带 `data-phone-screen`。

最终对齐结果（3x px，参考 | 渲染）：头部底 453|453、天气卡 483-815|482-816、
办文卡顶 840|840、办文图标行 1032-1168|1028-1164、办文卡底 1334|1334、
常用应用卡顶 1355|1356、三行图标 1547/1846/2107 | 1544/1849/2104，
图标横向位置 5 列逐个对齐；文字宽度一致（导航标题 181×58 vs 182×59、标签 150×35 vs 151×35）。
